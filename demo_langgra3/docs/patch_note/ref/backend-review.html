이 파일은 무엇인가
한 마디로: "자연어 프롬프트를 받아 신뢰할 수 있는 Python 노드 코드를 생성·검증·패키징하는 LangGraph 기반 실행 엔진"

사용자가 Cell에 자연어로 의도를 입력하면, 이 백엔드가 ① LLM으로 코드를 생성하고, ② LLM이 다시 그 코드를 의도 기준으로 검증하고, ③ 실제로 실행해 런타임 오류를 확인하고, ④ Human-in-the-loop 포인트를 거쳐, ⑤ 타입·스키마까지 완비된 재사용 가능한 함수로 래핑해 반환한다.

핵심 설계 철학은 "확률적 LLM을 결정론적 DAG로 제어"다. 코드 생성이 실패하면 피드백을 주입해 재시도(최대 3회)하고, 성공해도 인간 검토 포인트(human_review)를 통과해야 다음 단계로 넘어간다.

retry_count는 validate_intent와 execute 두 노드에서 각각 누적된다.
문제: 두 노드가 카운터를 공유하므로, 의도 실패 2회 + 실행 실패 1회 = 총 3회로 조기 종료될 수 있다. 실질적 재시도 기회가 기대보다 적다.
# edge_after_intent def edge_after_intent(state): if state["retry_count"] >= 3: # ← intent+exec 합산 카운트 return "failed" if not state["intent_ok"]: return "generate" return "execute"
Human-in-the-loop 실제 동작
현재 node_human_review의 한계
현재 node_human_review는 pass-through 노드다. 코드가 실행 통과되면 인간 확인 없이 자동으로 wrap으로 넘어간다.

명세에는 "Human-in-the-loop(일시정지 및 개입)"이 목표로 적혀 있지만, 현재 구현은 /cell/stop → /cell/resume 흐름을 프론트가 명시적으로 호출해야만 개입이 이루어진다. 즉 백엔드가 자동으로 멈추지 않는다.
코드 리뷰
잘한 점 / 아쉬운 점
✅
잘한 점 — 구조 설계
  • LangGraph의 DAG + MemorySaver 체크포인터 조합으로 상태를 노드 간에 안전하게 전달. 중간 실패 시 체크포인트에서 재개 가능한 구조.
  • 지연 초기화(Lazy Init)로 API 키 없이도 서버가 뜬다. 개발 환경에서의 DX가 좋다.
  • 모델명 prefix로 Anthropic/Ollama를 자동 분기. 로컬 모델 교체가 쉽고 테스트하기 유리하다.
  • SSE 스트리밍으로 각 단계(stage_start, log, result, done)를 실시간 전달. 프론트가 진행 상황을 즉각 반영할 수 있다.
  • Schema-First 설계: upstream_schema를 프롬프트에 주입해 셀 간 I/O 타입 연속성을 보장한다.
⚠️
아쉬운 점 — 보안 · 안정성
  • exec()가 격리되지 않음. namespace를 분리해도 os, subprocess, sys 등 위험 모듈에 대한 접근 차단이 없다. 악성 코드가 호스트에 영향을 줄 수 있다.
  • node_human_review가 pass-through. 명세의 HITL 개념과 달리, 현재는 인간이 개입하지 않아도 자동으로 wrap으로 진행된다.
  • retry_count가 intent·exec 구분 없이 합산. 의도 검증 실패와 실행 실패가 같은 카운터를 공유해 재시도 기회가 예상보다 줄어든다.
  • CORS가 allow_origins=["*"]. 프로덕션에서 모든 오리진 허용은 보안 위험. 개발 편의용으로만 허용해야 한다.
  • MemorySaver는 프로세스 재시작 시 소멸. 서버 재시작 시 실행 중이던 셀 상태가 전부 사라진다.
🔍
아쉬운 점 — 기능 완성도
  • wrap 노드의 JSON 파싱 실패 시 폴백(fallback)이 빈 스키마({})로 처리된다. 스키마 없는 노드가 파이프라인에 연결되면 다운스트림이 조용히 깨진다.
  • validate_intent가 LLM에게 LLM 코드를 리뷰시키는 구조. 같은 모델이 생성하고 검증하므로 같은 편향(bias)을 공유할 가능성이 높다.
  • cleanup 노드가 LLM 호출 1회를 소비하는데, 이는 AST 기반 정적 분석(예: autoflake, isort)으로 대체하면 속도와 비용을 모두 줄일 수 있다.
  • 실행 검증(execute)이 함수 호출이 아닌 코드 로드만 테스트. 실제 인자를 넣어 return 값이 올바른지는 검증하지 않는다.
💡
주목할 점 — 설계 의도
  • stream_log를 Annotated[list[str], lambda a, b: a+b]로 선언해 LangGraph의 reducer 패턴으로 로그를 누적. 노드 순서와 무관하게 전체 로그 추적이 가능하다.
  • _sse() 헬퍼 함수로 SSE 포맷을 추상화. 이벤트 타입(stage_start/log/result/done)이 명확히 분리되어 있어 프론트 파싱이 깔끔하다.
  • /cell/resume에서 update_state + as_node="human_review"를 활용해 인간이 수정한 코드를 체크포인트에 직접 주입하는 방식이 올바르다.
  • on_chain_end에서 누락될 수 있는 누적 필드를 get_state()로 직접 읽는 처리가 꼼꼼하다 (주석으로도 이유를 설명함).

개선 방향

from langgraph.types import interrupt async def node_human_review(state): # 이 시점에 그래프가 자동 일시정지 human_input = interrupt({ "code": state["generated_code"], "message": "코드를 검토하고 승인하거나 수정하세요" }) return { "generated_code": human_input.get("updated_code") or state["generated_code"], "stage": "human_review", }

문제 ① cleanup LLM 호출

미사용 변수 제거, import 정리는 LLM 없이도 정적 분석 도구로 처리 가능하다. LLM 호출 1회를 아끼면 비용과 지연 시간이 줄어든다.

문제 ② execute가 로드만 테스트

실제 함수 호출 없이 코드가 실행 가능한지만 본다. 사용자가 샘플 I/O를 제공하면, 해당 인자로 실제 호출해 return 값이 expected output과 일치하는지 검증해야 명세의 "자동 검증 시스템"이 완성된다.

# cleanup 교체 import autoflake, black cleaned = autoflake.fix_code(code, remove_unused_imports=True) cleaned = black.format_str(cleaned, mode=black.Mode()) # execute 강화 — 샘플 I/O 테스트 if sample_inputs: fn_name = list(namespace.keys())[-1] result = namespace[fn_name](**sample_inputs) assert result == expected_output, f"expected {expected_output}, got {result}"
